## 1. 一条数据流

原图/原标注 → 审计与抽样叠框 → 转换YOLO标签 → 加载预训练权重 → 训练/验证选best.pt → 独立整体与分组评估 → 失败案例与实验结论。预测只输出结果；有真实标注和匹配协议才能计算检测指标。原始文件保持不变；图片几何变换与框必须同步。

## 2. 训练、验证、测试与更新

| 概念 | 记住什么 |
|---|---|
| 训练集 | 参与梯度计算和参数学习 |
| 验证集 | 选择权重/超参，反复开发可能产生选择偏差 |
| 测试集 | 开发决策之外的最终检验，不用于反复调参 |
| batch / epoch | 每批样本数 / 遍历训练数据一轮；workers是数据加载进程数 |
| forward / loss | 前向计算预测 / 计算预测与监督的损失 |
| zero_grad / backward / step | 清除已有梯度 / 计算并累加梯度 / 按优化器规则更新参数 |
| 梯度累积 | 只清零一次，两次backward后一次step：使用累加梯度，更新一次 |

best.pt按当前Ultralytics实现的验证fitness选择，查版本/源码；不凭经验断言永远是多个指标加权。loss_box、loss_cls、loss_dfl的原理尚待学习验收，不在此宣称已掌握。

## 3. 输入大小与目标分组

Letterbox按比例缩放并补边，框同步缩放平移，不等于直接裁成正方形。具体训练增强另查args与实现。已有几何题：1920×1080图、原框(100,200,40,20)变为960方形时，框左上为(50,310)，宽高20×10。

当前自定义small按原图GT面积<32²；medium为[32²,96²)，large≥96²。16×48=768属于small；原图40×40即使缩成20×20仍属于medium。固定原图分组保证不同输入尺寸比较的是同一批GT；输入后的大小用于分析可见像素。32²不是所有数据集通用的唯一阈值，也不是实际物体的物理面积。

## 4. 匹配与指标

匹配通常要求类别一致、IoU达到评估阈值且一对一；具体忽略规则和最大预测数查协议。

- TP：正确匹配；FP：未被计为正确匹配的预测；FN：未被正确检出的真实目标。
- Precision=TP/(TP+FP)，Recall=TP/(TP+FN)。分母为0时按评测实现约定处理。
- 10个GT、12个预测、8个正确一对一匹配：TP8、FP4、FN2；Precision66.7%、Recall80%。
- 1个GT对应2个同类合格预测：最多1TP，另1FP。
- 真van预测car：car增加1FP，van增加1FN。**逐类分别计数是待复测项**；不能给两个类别各同时记一组FP/FN。
- 置信度0.8不是IoU，也不能直接当成80%正确率；高分仍可能错类/偏框/重复。没有完整真实框与类别时，无法计算完整Precision/Recall。

AP概括一类目标在不同分数截断下的PR表现，按指定插值协议计算；mAP在规定类别和IoU阈值上平均。AP50/75的数字指评估IoU而非置信度；IoU0.8可在AP50/AP75计TP，在AP90不能。框偏大可能造成严格IoU下AP下降，但仅凭mAP50与mAP50–95的差距不足以确定唯一根因。

术语复习：Precision的分母是参与评估的预测数；AP50指IoU匹配阈值0.5（50%），不是IoU=50，也不是某个置信度阈值的单点Precision。

类别宏平均Recall：先算各类再等权平均；实例微平均：先汇总TP/GT再相除。car检出80/100、bicycle检出2/10，宏平均50%，微平均82/110≈74.5%。两种口径不能交叉比较。

## 5. 三种后处理设置

| 设置 | 比较/作用 | 典型影响 |
|---|---|---|
| conf | 过滤低分预测 | 降低通常少漏检，但误检可能增加，Precision不保证怎样变化 |
| NMS IoU | 预测框与预测框去重，普通按类NMS保留高分框 | 同类两框IoU0.6：阈值0.5通常抑制低分框，阈值0.7保留两者；密集不同实例也可能被误删 |
| max_det | 每图所有类别合计的最终框数上限（本Demo） | 降低上限可能截掉正确预测；同一权重也可能Recall下降 |

NMS不看真实框；NMS IoU=0.7不改变AP50要求的预测与GT IoU≥0.5。以上阈值区别需换例复习，不能只记数字。

## 6. 实验比较与失败分析

先核对权重和轮次→指标列/口径→数据内容/划分→输入及后处理设置→软件/硬件。查看args.yaml、results.csv、best_val_summary.json、best_size_summary.json和数据YAML；同一路径不证明内容一样，比较哈希和数据指纹。CSV末轮与best.pt未必同一轮；独立排错的四项检查及文件定位尚待用户独立复测。

单次small AP11.75%→12.02%为+0.27**个百分点**，相对提升约2.30%；不证明稳定优势。多种子验证需按相同预算独立训练，比较均值和波动，不能重复评估同一个权重或增加epoch代替。

固定YOLOv8n 30轮权重，推理960→1280：small AP11.75%→15.75%（+4.00个百分点），固定阈值宏平均Recall22.95%→30.49%；large AP略降。支持当前验证条件下提高推理尺寸改善small，尚不证明1280训练更好、所有极小目标都改善或部署更合适；另看推理延迟/峰值显存。评估总耗时不直接等于FPS。

失败分析按「观察→多个解释→区分解释的证据→控制实验」组织。未匹配不直接证明模型幻觉或漏标。09/12类别标错是用户原标注核查反馈；保留原数据和旧指标。要修正数据，建立新版本统一重评，避免只改有利标签。

## 9. PyTorch与检测最低要求：先建立可追踪的数据流

| 知识 | 最低解释深度 | 常见混淆 |
|---|---|---|
| Tensor的shape/dtype/device | 图像batch常为[B,C,H,W]；数值类型、通道顺序及数值范围要匹配预处理；能打印检查输入/模型设备 | YOLO高级API可接收图像路径/数组，不表示底层网络直接计算路径字符串；不能把所有数据都强制转long |
| Dataset与DataLoader | Dataset通常提供按索引取样；DataLoader做批处理、采样/打乱及加载；检测中每图目标数可不同，原始targets不必是固定框数张量，整理方式由collate/框架决定 | shuffle改变顺序，不完成train/val划分，不修复同场景泄漏 |
| 梯度与优化器 | 参数requires_grad、计算图、loss.backward和step的职责；梯度默认累加；学习率影响更新步幅，实际更新还取决于优化器状态 | backward不直接更新权重；step不会自动清空梯度；验证指标不直接替代训练损失求梯度 |
| nn.Module的train/eval | 切换训练/推理模式，影响Dropout、BatchNorm等具体层 | eval不自动关闭梯度，no_grad也不自动切eval |
| no_grad与inference_mode | 关闭不必要的梯度追踪可节省推理开销；inference_mode还有额外约束。最低要求能解释验证/推理为什么通常不建训练计算图 | 不能据此推断模型参数或BN状态一定不变，要同时确认模式及实际代码 |
| checkpoint | 区分预训练、best/last权重、优化器状态；继续训练与从预训练重新启动不同 | 本Demo两次15/30轮resume=False，不是接续训练；固定权重重复评估不是多种子训练 |
| backbone/neck/head | 提取特征/融合多尺度特征/输出类别与位置相关预测；模型输入像素与特征图stride的联系 | 目标小于一个stride不自动证明分配不到正样本，须检查实际层和分配结果 |
| 损失与输出 | 理解位置监督、类别监督、输出到框解码、后处理到指标的不同环节 | 不把YOLO与DETR的原始输出、分配和后处理当成相同实现 |

特别区分两个同名API：`nn.Module.train()`主要设置模块训练模式；项目中的Ultralytics `YOLO(...).train(...)`是启动完整训练任务的高级接口。解释时须说明对象类型。Ultralytics高级验证/预测接口会管理内部模式，本项目不要求你重新实现整套训练框架。

YOLOv8常规检测损失的入门目标（尚待专门教学与闭卷验收）：

- `box_loss`：约束预测框的位置与形状，常规实现使用CIoU相关回归损失；不仅仅比较框中心。
- `cls_loss`：约束分类输出与分配得到的监督目标，常规实现使用基于logits的二元交叉熵；目标质量及权重受分配实现影响。
- `dfl_loss`：Distribution Focal Loss，学习框边缘相对参考位置的离散距离分布，服务于定位；它不是「再预测一次类别」，也不是推理NMS。

原路线把「分类/置信度/框回归」作为泛化概念。常规YOLOv8检测实现没有旧版YOLO那种独立objectness损失项，当前日志的box/cls/dfl应与实际Ultralytics版本和源码对应。最终推理分数的含义、损失系数和分配细节仍以使用版本为准；当前只要求能说清三个损失各约束什么，暂不要求默写全部公式。

最低口述验收：追踪一个batch的shape/设备/标签→前向与监督损失→清梯度/反传/更新→验证模式→保存和加载权重→预测与NMS→按协议匹配GT并汇总指标。最低操作验收：读一个batch打印关键字段，完成新图推理并解释输出，排查一个路径/设备/标签错误。原始PyTorch Dataset练习与Ultralytics数据封装分别解释，不因YOLO API跑通就推定已会手写DataLoader。
